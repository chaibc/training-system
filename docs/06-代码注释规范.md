# 代码注释规范（翰墨学堂）

> 目标：让接手的人只看代码就能理解「这段在做什么、为什么这么做、改了会影响什么」。
> 语言统一用**中文**，专业名词保留英文（如 JWT、HikariCP、MyBatis-Plus）。

## 一、Java 后端

### 1. 类级 Javadoc（每个 class / interface / enum 必须有）
```java
/**
 * 课次管理服务：负责课次的新增、修改、删除与冲突校验。
 *
 * <p>冲突校验覆盖四个维度：班级、任课教师、教室、学员（跨班时间重叠）。</p>
 */
@Service
public class LessonAdminService { ... }
```

### 2. public 方法 Javadoc
必须说明：做什么、入参含义、返回什么、可能抛什么业务异常、**有什么副作用**（写库 / 扣课时 / 记审计日志）。
```java
/**
 * 点名并消课。
 *
 * <p>副作用：写 attendance、按出勤状态扣减 hour_account 余额、写 hour_ledger 流水；
 * 同一学员同一次课重复点名会走「修正」分支，不会重复扣课时。</p>
 *
 * @param lessonId 课次 ID
 * @param items    学员出勤明细
 * @throws BusinessException 课次不存在或已结束（400）
 */
```

### 3. 私有方法 / 关键逻辑
- 私有方法上方一行 `//` 说明意图；
- 复杂 MyBatis-Plus Wrapper 条件、魔法数字（如 `7` 天、`0.5` 课时）、跨表联动、状态机流转，必须行内注释说明**为什么**。
```java
// 只统计未逻辑删除且仍在有效期内的授权
wrapper.eq(WorkAuth::getStatus, "ACTIVE");
```

### 4. 实体类
- 类级 Javadoc 指向对应表名与用途；
- 字段含义不直观时逐字段注释，**以 `sql/schema.sql` 的列注释为准**，不要自己发明含义。

## 二、管理后台（Vue 3）

1. **文件头注释块**：页面职责、主要交互、依赖的接口模块。
```js
/**
 * 班级与排课页：班级 CRUD、周课表、课次 CRUD。
 * 接口：/api/admin/classes、/api/admin/lessons
 */
```
2. `script` 里每个函数上方一行说明；`computed` / `watch` 说明触发条件与用途。
3. 模板用 `<!-- 顶部筛选区 -->`、`<!-- 班级表格 -->` 划分大区块。
4. 复杂表单校验、联动禁用条件必须注释原因。

## 三、微信小程序

1. **页面 JS 文件头**：页面职责、调用接口、页面参数、登录要求。
```js
/**
 * 课表页：展示已选学员的周课表。
 * 接口：/api/parent/schedule
 * 参数：childId（可选，缺省用全局当前学员）
 * 需登录：是
 */
```
2. 每个方法上方一行说明；`onLoad` 里的取参/鉴权逻辑要注释。
3. WXML 用 `<!-- 空状态 -->`、`<!-- 底部操作栏 -->` 标注区块。
4. WXSS 用 `/* ===== 课时卡片 ===== */` 标注样式区块。

## 四、禁止事项

- ❌ 重述代码的废话注释（`// 返回结果`、`// 循环遍历`、`// 设置 name`）。
- ❌ 猜测性、可能与实现不符的注释——不确定就不写。
- ❌ TODO 空话（除非确实记录了已知限制，并写清触发条件）。
- ❌ 修改任何代码行、重排格式、调整缩进。**本次只允许"新增注释行"**。
- ❌ 文件保存为带 BOM 的 UTF-8；Java/Vue/JS 一律 UTF-8 无 BOM，保持原有换行风格。

## 五、验收标准

1. 所有 class / 页面文件都有文件头注释；
2. 所有 public 方法有 Javadoc / 函数注释；
3. 关键业务规则（消课、冲突校验、审批联动、权限边界）能靠注释读懂；
4. `git diff --numstat` 中**删除行数为 0**（证明只加了注释）；
5. 后端 `mvn -q -DskipTests package`、前端 `npm run build` 通过。
