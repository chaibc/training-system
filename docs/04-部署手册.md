# 翰墨学堂 · 部署手册

> 面向：不熟悉后端的开发者 / 机构运维
> 目标：从一台全新阿里云服务器开始，部署管理后台、Java 后端、MySQL，并让微信小程序连接线上接口。
> 本文以 **Ubuntu 22.04** 为主，附 **Alibaba Cloud Linux 3 / CentOS 系** 的差异命令。
> 服务器迁移见 `docs/05-服务器迁移指南.md`。

---

## 零、先准备这些信息

部署前请把下面信息记在记事本里：

| 项目 | 示例 | 在哪里获取 |
|------|------|------------|
| 已备案域名 | `hanmo.example.com` | 你的域名服务商 / 阿里云备案控制台 |
| 服务器公网 IP | `47.xx.xx.xx` | 阿里云 ECS 控制台 |
| 服务器 SSH 账号 | `root` | 阿里云 ECS 控制台 |
| 服务器系统 | Ubuntu 22.04 或 Alibaba Cloud Linux 3 | ECS 控制台 |
| MySQL 密码 | 自己生成强密码 | 本文第 4 节创建 |
| JWT 密钥 | `openssl rand -base64 48` 生成 | 本文第 5 节 |
| 小程序 AppID | `wx...` | 微信公众平台 → 开发管理 → 开发设置 |
| 小程序 AppSecret | `...` | 同上，只显示一次，注意保密 |
| 管理端域名 | 通常与 API 同域，如 `https://hanmo.example.com` | 自己确定 |

> 域名必须完成 ICP 备案；微信小程序要求 HTTPS，且域名不能带端口。

### 服务器建议配置

- 当前规模（<100 学员、<5 教师）：2 核 4G、40G 系统盘足够。
- 未来 <1000 总人数：2 核 4G 仍可，建议 4 核 8G、100G 盘更稳。
- 带宽 3–5 Mbps 起；图片较多可配 OSS/CDN（当前版本用本地上传目录，后续可迁移）。
- 操作系统：Ubuntu 22.04 LTS 或 Alibaba Cloud Linux 3。**不要用 Windows Server**。

## 一、整体结构

```text
用户浏览器 / 微信小程序
        │
        ▼
   Nginx :80 / :443
     ├── /                 → /var/www/hanmo-admin（Vue 管理端静态文件）
     ├── /api/             → 127.0.0.1:8080（Spring Boot）
     ├── /uploads/         → /data/hanmo/uploads（图片）
     └── /actuator/health  → 仅本机可访问
        │
        ▼
   Spring Boot :8080
        │
        ▼
   MySQL 8 :3306（只监听 127.0.0.1）
```

端口规划：

| 端口 | 用途 | 是否对公网开放 |
|------|------|:--------------:|
| 22 | SSH | 建议限制来源 IP |
| 80 | HTTP（跳转 HTTPS / 证书验证） | 是 |
| 443 | HTTPS | 是 |
| 8080 | Java 后端 | **否** |
| 3306 | MySQL | **否** |

## 二、本地打包（在你的 Windows 电脑上）

### 2.1 确认环境

在项目根目录打开 PowerShell / Git Bash：

```bash
java -version
mvn -version
node -v
npm -v
```

应看到：

- Java 17
- Maven 3.8+
- Node 20+（18 也可，推荐 20）

如果 `mvn` 不存在，安装 Maven 后把 `bin` 加入 PATH。

### 2.2 打包后端

```bash
cd server
mvn clean package -DskipTests
```

产物：

```text
server/target/hanmo-server.jar
```

确认文件存在并约 40MB。

### 2.3 构建管理端

```bash
cd ../admin-web
npm ci
npm run build
```

产物目录：

```text
admin-web/dist/
  index.html
  assets/
```

> `npm ci` 按 `package-lock.json` 安装，比 `npm install` 更适合部署。若没有 lock 文件则用 `npm install`。

### 2.4 准备上传文件

把下面内容准备好，之后用 `scp` 传到服务器：

```text
server/target/hanmo-server.jar
admin-web/dist/
sql/schema.sql
sql/seed-prod.sql
deploy/nginx/hanmo.conf
deploy/systemd/hanmo-server.service
deploy/env/hanmo.env.example
deploy/scripts/backup.sh
deploy/scripts/health-check.sh
deploy/scripts/deploy-jar.sh
deploy/scripts/logrotate-hanmo
deploy/seed-uploads/demo/（可选，演示图片）
```

在项目根目录执行（把 `47.xx.xx.xx` 换成服务器 IP）：

```bash
scp server/target/hanmo-server.jar root@47.xx.xx.xx:/tmp/hanmo-server.jar
ssh root@47.xx.xx.xx "mkdir -p /tmp/hanmo-admin"
scp -r admin-web/dist/* root@47.xx.xx.xx:/tmp/hanmo-admin/
scp sql/schema.sql sql/seed-prod.sql root@47.xx.xx.xx:/tmp/
scp deploy/nginx/hanmo.conf root@47.xx.xx.xx:/tmp/hanmo.conf
scp deploy/systemd/hanmo-server.service root@47.xx.xx.xx:/tmp/
scp deploy/env/hanmo.env.example root@47.xx.xx.xx:/tmp/
scp deploy/scripts/backup.sh deploy/scripts/health-check.sh     deploy/scripts/deploy-jar.sh deploy/scripts/logrotate-hanmo root@47.xx.xx.xx:/tmp/
```

> 后续命令直接使用 `/tmp/hanmo.conf`、`/tmp/hanmo-server.service`、`/tmp/hanmo.env.example` 等文件名。

## 三、服务器初始化

### 3.1 登录服务器

Windows 可用 PowerShell：

```bash
ssh root@47.xx.xx.xx
```

首次登录输入 yes，再输入密码。后续建议配置 SSH 密钥登录。

### 3.2 设置时区

```bash
timedatectl set-timezone Asia/Shanghai
timedatectl
```

确认输出包含 `Asia/Shanghai`。

### 3.3 更新系统

**Ubuntu：**

```bash
apt update && apt upgrade -y
apt install -y curl wget unzip vim rsync tar gzip ca-certificates gnupg lsb-release
```

**Alibaba Cloud Linux 3 / CentOS：**

```bash
dnf update -y
dnf install -y curl wget unzip vim rsync tar gzip ca-certificates
```

### 3.4 创建运行用户和目录

不要用 root 跑 Java。创建独立用户：

```bash
useradd --system --create-home --home-dir /home/hanmo --shell /sbin/nologin hanmo
mkdir -p /data/hanmo/app /data/hanmo/uploads /data/hanmo/logs /data/hanmo/backups /data/hanmo/scripts
chown -R hanmo:hanmo /data/hanmo
chmod 755 /data/hanmo
chmod 750 /data/hanmo/app /data/hanmo/logs /data/hanmo/backups
chmod 755 /data/hanmo/uploads
```

> Nginx 需要读取 `/data/hanmo/uploads`。**稍后安装 Nginx 后**，把 Nginx 用户加入 `hanmo` 组（Ubuntu 是 `www-data`，Alibaba Cloud Linux/CentOS 通常是 `nginx`）：
>
> ```bash
> usermod -aG hanmo www-data    # 或 nginx
> systemctl restart nginx
> ```
>
> 这样上传文件即使按 640 权限创建，Nginx 也能通过组权限读取。

说明：

- `/data/hanmo/app`：jar
- `/data/hanmo/uploads`：用户上传图片（**必须随数据库一起备份**）
- `/data/hanmo/logs`：日志
- `/data/hanmo/backups`：备份
- `/data/hanmo/scripts`：运维脚本

## 四、安装 MySQL 8

### 4.1 Ubuntu 安装

```bash
apt install -y mysql-server
systemctl enable --now mysql
mysql --version
```

执行安全初始化：

```bash
mysql_secure_installation
```

建议：

- 设置 root 密码：是
- 删除匿名用户：是
- 禁止 root 远程登录：是
- 删除 test 库：是
- 重新加载权限表：是

### 4.2 Alibaba Cloud Linux 3 / CentOS 安装

先确认系统版本：

```bash
cat /etc/os-release
```

安装 MySQL 官方 8.0 社区版（EL8 源，适用于 Alibaba Cloud Linux 3）：

```bash
dnf install -y https://repo.mysql.com/mysql80-community-release-el8-9.noarch.rpm
dnf install -y mysql-community-server
systemctl enable --now mysqld
systemctl status mysqld --no-pager
```

首次启动会生成临时 root 密码：

```bash
grep 'temporary password' /var/log/mysqld.log
```

用临时密码登录并修改：

```bash
mysql -uroot -p
```

```sql
ALTER USER 'root'@'localhost' IDENTIFIED BY '你的Root强密码';
FLUSH PRIVILEGES;
EXIT;
```

然后执行：

```bash
mysql_secure_installation
```

> 如果 `dnf install` 提示源冲突，先 `dnf module disable mysql -y` 或参考 MySQL 官方文档更换对应 EL 版本源。不要安装 MariaDB 替代 MySQL 8 的导入脚本（存在兼容差异）。

### 4.3 MySQL 基础配置

编辑配置文件：

- Ubuntu：`/etc/mysql/mysql.conf.d/mysqld.cnf`
- Alibaba Cloud Linux：`/etc/my.cnf`

在 `[mysqld]` 下增加/确认：

```ini
bind-address = 127.0.0.1
character-set-server = utf8mb4
collation-server = utf8mb4_general_ci
default-time-zone = '+08:00'
max_connections = 100
```

重启：

```bash
# Ubuntu
systemctl restart mysql
# Alibaba Cloud Linux
systemctl restart mysqld
```

确认：

```bash
mysql -uroot -p -e "SHOW VARIABLES LIKE 'character_set_server'; SHOW VARIABLES LIKE 'time_zone';"
```

### 4.4 创建数据库与业务账号

登录 MySQL：

```bash
mysql -uroot -p
```

执行（把密码换成你的强密码，建议字母+数字+符号，至少 16 位）：

```sql
CREATE DATABASE IF NOT EXISTS `hanmo_calligraphy`
  DEFAULT CHARACTER SET utf8mb4
  COLLATE utf8mb4_general_ci;

CREATE USER 'hanmo'@'127.0.0.1' IDENTIFIED BY '替换为数据库强密码';
GRANT ALL PRIVILEGES ON `hanmo_calligraphy`.* TO 'hanmo'@'127.0.0.1';
FLUSH PRIVILEGES;
EXIT;
```

测试：

```bash
mysql -h127.0.0.1 -uhanmo -p -e "SHOW DATABASES;"
```

### 4.5 导入表结构

把 `sql/schema.sql` 上传到服务器 `/tmp/`，然后：

```bash
# Ubuntu（root 使用 auth_socket）
sudo mysql < /tmp/schema.sql
# Alibaba Cloud Linux / CentOS（root 密码登录）
# mysql -uroot -p < /tmp/schema.sql
```

验证表数量（应为 38）：

```bash
mysql -h127.0.0.1 -uhanmo -p -N -e \
  "SELECT COUNT(*) FROM information_schema.tables WHERE table_schema='hanmo_calligraphy';"
```

### 4.6 导入生产初始化数据

**生产环境只用 `seed-prod.sql`，不要执行 `seed.sql`（那是演示数据）。**

```bash
mysql -h127.0.0.1 -uhanmo -p < /tmp/seed-prod.sql
```

验证管理员：

```bash
mysql -h127.0.0.1 -uhanmo -p -e \
  "SELECT id,username,name,user_type,status FROM hanmo_calligraphy.sys_user;"
```

应只有 admin 一个账号。

> `seed-prod.sql` 的机构信息是占位内容，部署后必须在管理后台改为真实信息。

## 五、安装 Java 17 与部署后端

### 5.1 安装 Java 17

**Ubuntu：**

```bash
apt install -y openjdk-17-jdk
java -version
```

**Alibaba Cloud Linux 3 / CentOS：**

```bash
dnf install -y java-17-openjdk java-17-openjdk-devel
java -version
```

确认 java 路径：

```bash
readlink -f "$(command -v java)"
```

通常是 `/usr/bin/java`。如果不是，修改 systemd 文件里的 `ExecStart`。

### 5.2 创建环境变量文件

```bash
mkdir -p /etc/hanmo
cp /tmp/hanmo.env.example /etc/hanmo/hanmo.env
chown root:hanmo /etc/hanmo/hanmo.env
chmod 640 /etc/hanmo/hanmo.env
```

生成 JWT 密钥：

```bash
openssl rand -base64 48
```

编辑：

```bash
vim /etc/hanmo/hanmo.env
```

填入：

```ini
TZ=Asia/Shanghai
DB_HOST=127.0.0.1
DB_PORT=3306
DB_NAME=hanmo_calligraphy
DB_USER=hanmo
DB_PASSWORD=第 4.4 步创建的密码
JWT_SECRET=上一步生成的随机字符串
UPLOAD_DIR=/data/hanmo/uploads
CORS_ORIGINS=https://hanmo.example.com
WX_APP_ID=你的小程序AppID
WX_APP_SECRET=你的小程序AppSecret
WX_DEV_MODE=false
```

注意：

- 密码中如果有 `#`、空格、`$`，用单引号包起来，例如 `DB_PASSWORD='Abc#123$xyz'`。
- `CORS_ORIGINS` 改成真实域名；临时可用服务器 IP + 端口，但上线后必须是 HTTPS 域名。
- 生产 `WX_DEV_MODE=false`，否则任何人可用演示 code 登录。

### 5.3 上传 jar

在本地执行：

```bash
scp server/target/hanmo-server.jar root@47.xx.xx.xx:/tmp/hanmo-server.jar
```

在服务器执行：

```bash
install -o hanmo -g hanmo -m 640 /tmp/hanmo-server.jar /data/hanmo/app/hanmo-server.jar
mkdir -p /data/hanmo/uploads
chown -R hanmo:hanmo /data/hanmo/uploads
```

（可选）如果需要演示机构图片：

```bash
mkdir -p /data/hanmo/uploads/demo
cp /tmp/demo/*.jpg /data/hanmo/uploads/demo/
chown -R hanmo:hanmo /data/hanmo/uploads/demo
```

生产环境建议由机构后台上传真实图片；不复制演示图也可以。

### 5.4 安装 systemd 服务

```bash
cp /tmp/hanmo-server.service /etc/systemd/system/hanmo-server.service
systemctl daemon-reload
systemctl enable hanmo-server
systemctl start hanmo-server
```

查看状态：

```bash
systemctl status hanmo-server --no-pager
```

检查健康：

```bash
curl http://127.0.0.1:8080/actuator/health
```

应返回：

```json
{"status":"UP"}
```

查看日志：

```bash
tail -f /data/hanmo/logs/hanmo-server.log
journalctl -u hanmo-server -f
```

常见启动失败：

- `DB_PASSWORD` 错 → 日志中 `Access denied for user 'hanmo'`
- 表未导入 → `Table 'hanmo_calligraphy.sys_user' doesn't exist`
- 端口被占用 → `Port 8080 was already in use`
- 目录权限 → `Permission denied`，执行 `chown -R hanmo:hanmo /data/hanmo`

### 5.5 测试后端接口

```bash
curl http://127.0.0.1:8080/api/public/home
```

应返回 JSON 且 `code=0`。

登录测试：

```bash
curl -s -X POST http://127.0.0.1:8080/api/auth/login \
  -H 'Content-Type: application/json' \
  -d '{"username":"admin","password":"Admin@123456"}'
```

返回 token 即正常。

> 此时不要急着关 SSH；先确认 8080 正常，再做 Nginx。

## 六、部署管理端与 HTTPS

### 6.1 上传管理端静态文件

在本地执行：

```bash
ssh root@47.xx.xx.xx "mkdir -p /tmp/hanmo-admin"
scp -r admin-web/dist/* root@47.xx.xx.xx:/tmp/hanmo-admin/
```

服务器：

```bash
mkdir -p /var/www/hanmo-admin
rm -rf /var/www/hanmo-admin/*
cp -r /tmp/hanmo-admin/* /var/www/hanmo-admin/
chown -R root:root /var/www/hanmo-admin
find /var/www/hanmo-admin -type d -exec chmod 755 {} \;
find /var/www/hanmo-admin -type f -exec chmod 644 {} \;
```

> 静态文件由 root 拥有、Nginx 只读即可，不需要让 Nginx 写目录。Ubuntu Nginx 用户是 `www-data`，Alibaba Cloud Linux / CentOS 通常是 `nginx`。

### 6.2 安装 Nginx

**Ubuntu：**

```bash
apt install -y nginx
systemctl enable --now nginx
```

**Alibaba Cloud Linux 3 / CentOS：**

```bash
dnf install -y nginx
systemctl enable --now nginx
```

确认：

```bash
nginx -v
```

把 Nginx 用户加入 `hanmo` 组，使其能读取上传文件：

```bash
# Ubuntu
usermod -aG hanmo www-data
# Alibaba Cloud Linux / CentOS
# usermod -aG hanmo nginx

systemctl restart nginx
groups www-data      # 或 groups nginx，应看到 hanmo
```

### 6.3 配置域名解析

在域名服务商控制台添加 A 记录：

```text
主机记录：hanmo
记录类型：A
记录值：47.xx.xx.xx
TTL：600
```

等待生效：

```bash
nslookup hanmo.example.com
ping hanmo.example.com
```

> 必须等 DNS 指向本服务器后再申请证书，否则 Let's Encrypt 验证失败。

### 6.4 配置阿里云安全组

在 ECS 控制台 → 安全组 → 入方向，添加：

| 端口 | 来源 | 说明 |
|------|------|------|
| 22 | 你的公网 IP/32（推荐） | SSH |
| 80 | 0.0.0.0/0 | HTTP 跳转与证书 |
| 443 | 0.0.0.0/0 | HTTPS |
| 8080 | 不开放 | 仅本机 |
| 3306 | 不开放 | 仅本机 |

如果使用服务器防火墙（ufw/firewalld），同步放行：

```bash
# Ubuntu ufw
ufw allow 22/tcp
ufw allow 80/tcp
ufw allow 443/tcp
ufw enable
ufw status

# Alibaba Cloud Linux firewalld
firewall-cmd --permanent --add-service=ssh
firewall-cmd --permanent --add-service=http
firewall-cmd --permanent --add-service=https
firewall-cmd --reload
firewall-cmd --list-all
```

### 6.5 先用 HTTP 申请证书

创建临时 HTTP 站点（只用于证书验证）：

```bash
mkdir -p /var/www/certbot
cat > /etc/nginx/sites-available/hanmo-bootstrap.conf <<'EOF'
server {
    listen 80;
    server_name hanmo.example.com;
    location /.well-known/acme-challenge/ {
        root /var/www/certbot;
    }
    location / {
        return 200 "bootstrap";
    }
}
EOF
ln -sf /etc/nginx/sites-available/hanmo-bootstrap.conf /etc/nginx/sites-enabled/hanmo-bootstrap.conf
rm -f /etc/nginx/sites-enabled/default
nginx -t && systemctl reload nginx
```

> Alibaba Cloud Linux / CentOS 的 Nginx 可能没有 `sites-available`，配置目录是 `/etc/nginx/conf.d/`。这种情况下把上面文件写到 `/etc/nginx/conf.d/hanmo-bootstrap.conf`，跳过软链接。

安装 certbot：

**Ubuntu：**

```bash
apt install -y certbot python3-certbot-nginx
```

**Alibaba Cloud Linux 3 / CentOS：**

```bash
dnf install -y certbot python3-certbot-nginx
```

> 如果提示找不到 `python3-certbot-nginx`，先执行 `dnf install -y certbot`，再用下面的 `certonly --webroot` 方式申请证书；证书申请成功后的 Nginx 配置步骤不变。也可用 `python3 -m pip install certbot` 安装。

申请证书：

```bash
certbot certonly --webroot -w /var/www/certbot \
  -d hanmo.example.com \
  --agree-tos \
  -m 你的邮箱@example.com \
  --non-interactive
```

成功后会生成：

```text
/etc/letsencrypt/live/hanmo.example.com/fullchain.pem
/etc/letsencrypt/live/hanmo.example.com/privkey.pem
```

验证自动续期：

```bash
certbot renew --dry-run
```

> certbot 的 systemd timer 会每天检查并自动续期；不要删除 `/etc/letsencrypt`。

### 6.6 安装正式 Nginx 配置

上传并修改：

```bash
cp /tmp/hanmo.conf /etc/nginx/sites-available/hanmo.conf
vim /etc/nginx/sites-available/hanmo.conf
```

替换 `hanmo.example.com` 为真实域名，确认证书路径。

启用：

```bash
ln -sf /etc/nginx/sites-available/hanmo.conf /etc/nginx/sites-enabled/hanmo.conf
rm -f /etc/nginx/sites-enabled/hanmo-bootstrap.conf
nginx -t
systemctl reload nginx
```

> 如果使用 `/etc/nginx/conf.d/`，把文件放到那里并确保默认站点没有抢占 `server_name`。
> 注意 `/data/hanmo` 目录本身必须是 755，否则 Nginx 无法读取 `/data/hanmo/uploads`。

### 6.7 验证 HTTPS

```bash
curl -I https://hanmo.example.com/
curl https://hanmo.example.com/api/public/home
```

浏览器打开：

- `https://hanmo.example.com/` → 管理端登录页
- `https://hanmo.example.com/api/public/home` → JSON

常见问题：

- 502：后端没启动或端口不是 8080，`systemctl status hanmo-server`
- 404：管理端 dist 没放对，检查 `/var/www/hanmo-admin/index.html`
- 证书错误：DNS 未生效或证书域名不匹配
- 上传 413：Nginx `client_max_body_size` 未生效

## 七、微信小程序上线配置

### 7.1 注册与 AppID

1. 登录微信公众平台：`https://mp.weixin.qq.com/`
2. 注册小程序，完成主体认证。
3. 开发管理 → 开发设置，复制 **AppID** 和 **AppSecret**。
4. 把 AppID/AppSecret 写入 `/etc/hanmo/hanmo.env`：

```ini
WX_APP_ID=wx...
WX_APP_SECRET=...
WX_DEV_MODE=false
```

5. 重启后端：

```bash
systemctl restart hanmo-server
```

### 7.2 配置服务器域名

微信公众平台 → 开发管理 → 开发设置 → 服务器域名：

| 类型 | 填写 |
|------|------|
| request 合法域名 | `https://hanmo.example.com` |
| uploadFile 合法域名 | `https://hanmo.example.com` |
| downloadFile 合法域名 | `https://hanmo.example.com`（如使用图片预览/下载） |

要求：

- 必须 HTTPS，证书有效。
- 域名已备案。
- 不能带端口、不能是 IP。
- 修改后需在开发者工具重新编译/清缓存。

### 7.3 修改小程序生产配置

编辑 `miniprogram/config.js`：

```js
const ENV = 'production';

const CONFIG = {
  production: {
    baseUrl: 'https://hanmo.example.com',
    apiBase: 'https://hanmo.example.com/api'
  }
};
```

同时把 `miniprogram/project.config.json` 的 `appid` 从 `touristappid` 改为真实 AppID。

### 7.4 开发者工具导入与预览

1. 微信开发者工具 → 导入项目 → 选择 `miniprogram/`。
2. 填入 AppID。
3. 开发阶段可勾选「不校验合法域名…」；上线前关闭。
4. 编译，检查登录、课程、作品、课表、请假、报名、教师端。
5. 上传 → 填写版本号与备注 → 设为体验版。
6. 用管理员/教师/家长微信扫码体验。
7. 体验无误后提交审核，审核通过后发布。

### 7.5 隐私与合规

- 小程序后台填写《用户隐私保护指引》，说明收集手机号、学员姓名/年龄/学校、作品图片的用途。
- 家长首次提交试听/绑定前需勾选隐私说明。
- 作品展示必须取得家长授权；未授权作品不得展示。
- 机构资质须真实可核验，不要虚构。
- 不使用短信验证码与模板消息；不要在小程序收集身份证等非必要信息。

## 十、版本更新流程

### 10.1 后端更新

本地：

```bash
cd server
mvn clean package -DskipTests
scp target/hanmo-server.jar root@47.xx.xx.xx:/tmp/hanmo-server.jar
```

服务器：

```bash
bash /data/hanmo/scripts/deploy-jar.sh /tmp/hanmo-server.jar
```

脚本会：

1. 备份旧 jar 到 `/data/hanmo/backups/releases/`
2. 覆盖新 jar
3. 重启服务
4. 输出状态和最近日志

### 10.2 管理端更新

本地：

```bash
cd admin-web
npm ci
npm run build
scp -r dist/* root@47.xx.xx.xx:/tmp/hanmo-admin/
```

服务器：

```bash
rm -rf /var/www/hanmo-admin/*
cp -r /tmp/hanmo-admin/* /var/www/hanmo-admin/
chown -R www-data:www-data /var/www/hanmo-admin   # 或 nginx:nginx
nginx -t && systemctl reload nginx
```

### 10.3 小程序更新

1. 修改 `config.js`（如需域名变更）。
2. 开发者工具上传新版本。
3. 提交审核 → 发布。
4. 小程序端 `wx.getUpdateManager` 会提示用户重启更新。

### 10.4 数据库变更

当前版本不自动执行 schema 变更。后续如新增表/字段：

1. 先备份数据库。
2. 在测试环境执行变更 SQL。
3. 低峰期在生产执行。
4. 验证接口。
5. 保留回滚 SQL。

## 十一、排障手册

| 现象 | 排查 |
|------|------|
| 管理端打不开 / 502 | `systemctl status hanmo-server`；`curl 127.0.0.1:8080/actuator/health`；看 Nginx error log |
| 登录提示服务器内部错误 | 看 `/data/hanmo/logs/hanmo-server.log`，多为数据库连接/表缺失 |
| 图片 404 | 检查 `UPLOAD_DIR`、`/data/hanmo/uploads`、Nginx `alias` 路径 |
| 上传 413 | Nginx `client_max_body_size 20m` 并 reload |
| 上传 401 | 前端请求是否带 Token；小程序 uploadFile header 是否带 Authorization |
| 小程序请求失败 | 合法域名是否配置；HTTPS 是否有效；`config.js` 是否 production |
| 微信登录 404 | 教师手机号与后台档案不一致；家长登录不要传 phone |
| 微信登录 409 | 该微信已绑定其他账号；后台解绑后再试 |
| 后台锁定 | 等 5 分钟；或数据库中清零 `failed_attempts`/`locked_until`（谨慎） |
| 时间差 8 小时 | 服务器时区、MySQL `default-time-zone`、systemd `TZ` 三处都要 Asia/Shanghai |
| 端口被占用 | `ss -lntp | grep 8080`，停掉冲突进程 |
| 磁盘满 | `df -h`；清理旧日志/备份；扩容云盘 |
| 内存不足 | `free -h`；`-Xmx512m`；升级配置或减少并发 |
| 证书过期 | `certbot renew --dry-run`；检查 80 端口/ACME 路径 |
| 微信公众号提示域名不合法 | 域名需 HTTPS、备案、无端口；修改后重新编译 |

### 紧急重启

```bash
systemctl restart hanmo-server
systemctl reload nginx
```

### 查看最近错误

```bash
journalctl -u hanmo-server -n 100 --no-pager
tail -n 200 /data/hanmo/logs/hanmo-server.log
tail -n 100 /var/log/nginx/hanmo.error.log
```
