# 已知问题清单（2026-11-05）

> 来源：本次全量补注释时对代码的逐文件审阅（7 个并行任务 + 主线复核）。
> **本清单只做记录，未修改任何业务逻辑**。严重度按「是否会造成数据错误 / 越权 / 用户可感知故障」划分。
> 标注「已验证」的是主线亲自核对过的；其余为子任务报告、建议修复前再确认一次。

## 修复记录

| 日期 | 问题 | 修复方式 | 验证 |
|---|---|---|---|
| 2026-11-05 | **P0-1 通用 CRUD 绕过业务校验** | `BaseCrudController` 新增 `writeChannelsEnabled()` 开关；作品、点名记录、课时账户、课时流水、请假、作品授权、补课、缴费、试听共 9 个控制器覆盖为 `false`，`POST/PUT/DELETE` 统一返回 405，只保留查询通道。同时给 `GlobalExceptionHandler` 补上 `405 → METHOD_NOT_ALLOWED` 映射 | 实测：`POST /api/admin/attendance-records`、`POST /api/admin/works`、`PUT /api/admin/leave/1` 均返回 HTTP 405；`GET /list` 正常 200 |

| 2026-11-05 | **P1-7 作品授权撤回范围过宽** | `WorkAdminService#revokeAuth` 改为：该学员仍有其他 ACTIVE 授权时不下架作品；只有撤回最后一份授权才批量置 HIDDEN | 实测：两个家长都有授权时撤回其一 → 作品保持 DISPLAYED；撤回最后一份 → 2 件作品变 HIDDEN |
| 2026-11-05 | **P1-9 作品模块无审计** | `WorkAdminService` 注入 `SysAuditLogMapper`，上传/审核/授权补录/授权撤回四个动作都写 `sys_audit_log`；控制器用 `@AuthenticationPrincipal` 注入操作人 | 实测：审计列表出现「作品上传」「作品审核」「授权补录」「授权撤回」四类记录，内容含学员、家长、作品名与状态 |

| 12 | `BusinessException(500)` 被映射成 HTTP 400 | `GlobalExceptionHandler` | 响应体 code=500 但 HTTP 状态 400，前端可能按 400 处理 |
| 13 | 通用 update 语义缺陷 | `BaseCrudController#update` | 反射写 id + MyBatis-Plus 跳过 null → 无法把字段置空；id 不存在也返回成功 |

| 15 | 家长自动建号手机号恒为空 | `AuthService#wxLogin` | `parent.setPhone(request.getPhone())` 该分支下必为 null，新家长 `sys_user.phone` 与 `parent_profile.phone` 都为空 |
| 16 | 若干空指针/重复查询 | `MiniParentService`、`MiniTeacherService`、`MiniPublicService` | `createBinding` 的 `studentNo` 为 null 会 NPE；`priceNote` 的 `unit` 为 null 会 NPE；`lessonDetail` 同一请假查两次；`requireLessonStudent` 统计 `class_student` 未过滤 status |
| 17 | 点赞无防重复 | `MiniPublicService#like` | 返回 `likeCount` 是"读到的旧值+1"，高并发与库中值可能不一致（自增 SQL 本身安全） |
| 18 | 上传只校验扩展名 | `common/UploadController` | 未校验文件头 magic bytes，伪造扩展名的非图片可落盘（路径穿越已有防护） |
| 19 | H2 控制台无条件放行 | `SecurityConfig` | `/h2-console/**` permitAll；生产 `application-prod.yml` 已关闭 H2 控制台，建议加 profile 条件 |
