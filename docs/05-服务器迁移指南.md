# 翰墨学堂 · 服务器迁移指南

> 场景：系统先部署在临时阿里云服务器，后续迁移到客户服务器。
> 目标：**数据不丢、图片不丢、小程序和后台可用**。
> 迁移前请先完整阅读 `docs/04-部署手册.md`，新服务器初始化步骤与它相同。

---

## 一、先判断迁移类型

### 类型 A：域名不变，只换服务器（最常见）

旧：`https://hanmo.example.com` → 旧服务器 IP
新：`https://hanmo.example.com` → 新服务器 IP

需要做：

- 迁移数据库、上传文件、jar、管理端静态文件、环境变量
- 把 HTTPS 证书复制到新服务器（或重新申请）
- 修改 DNS A 记录
- 微信小程序**不需要**改域名，也不需要重新审核（只要域名不变）

### 类型 B：域名也换

旧：`https://old.example.com`
新：`https://new.example.com`

除了类型 A 的全部工作，还需要：

- 新域名完成 ICP 备案
- 重新申请 HTTPS 证书
- 修改后端 `CORS_ORIGINS`
- 修改小程序 `config.js` 并重新上传/审核
- 微信公众平台修改 request/uploadFile 合法域名
- 旧域名可做 301 跳转（可选）

> 如果客户要求换域名，建议先在旧域名完成迁移，再单独切换域名，降低一次变更的风险。

## 三、迁移前一周：降低风险

### 3.1 降低 DNS TTL

在域名控制台把 A 记录 TTL 从 600/3600 改为 **300 秒**，至少提前 24 小时。这样切换后生效快、回滚也快。

### 3.2 备份演练

在旧服务器执行一次备份，并尝试在测试库恢复，确认备份文件可用：

```bash
sudo -u hanmo /data/hanmo/scripts/backup.sh
ls -lh /data/hanmo/backups/
```

### 3.3 记录当前状态

```bash
# 版本
sha256sum /data/hanmo/app/hanmo-server.jar
java -version
mysql --version
nginx -v
# 数据量
mysql -h127.0.0.1 -uhanmo -p -e "
SELECT 'student' AS t, COUNT(*) AS c FROM hanmo_calligraphy.student
UNION ALL SELECT 'parent_student', COUNT(*) FROM hanmo_calligraphy.parent_student
UNION ALL SELECT 'enrollment', COUNT(*) FROM hanmo_calligraphy.enrollment
UNION ALL SELECT 'payment_record', COUNT(*) FROM hanmo_calligraphy.payment_record
UNION ALL SELECT 'attendance', COUNT(*) FROM hanmo_calligraphy.attendance
UNION ALL SELECT 'leave_request', COUNT(*) FROM hanmo_calligraphy.leave_request
UNION ALL SELECT 'work', COUNT(*) FROM hanmo_calligraphy.work
UNION ALL SELECT 'hour_ledger', COUNT(*) FROM hanmo_calligraphy.hour_ledger;"
# 金额/课时合计
mysql -h127.0.0.1 -uhanmo -p -e "
SELECT SUM(amount) AS payment_total FROM hanmo_calligraphy.payment_record;
SELECT SUM(remaining_hours) AS remaining_total, SUM(used_hours) AS used_total FROM hanmo_calligraphy.hour_account;"
```

把这些数字保存到迁移记录里，迁移后逐项对比。

## 四、新服务器初始化（迁移日前完成）

按 `docs/04-部署手册.md` 完成到以下程度：

1. 系统更新、时区、`hanmo` 用户、目录。
2. 安装 Java 17、MySQL 8、Nginx、certbot。
3. MySQL 创建数据库与 `hanmo` 用户。
4. **先不要导入业务数据**（迁移时统一导入）。
5. 安装目录：

```text
/data/hanmo/app
/data/hanmo/uploads
/data/hanmo/logs
/data/hanmo/backups
/data/hanmo/scripts
/etc/hanmo/hanmo.env
/var/www/hanmo-admin
```

6. 安全组 8080、3306 不对外开放。

> 新服务器可以先不启动 hanmo-server，等数据恢复并核对后再启动。

## 五、正式迁移（建议低峰期，约 15–40 分钟）

### 5.1 通知与冻结

1. 提前通知家长/教师：某时间段系统不可用。
2. 选择晚上/周末低峰。
3. 停止旧后端，防止迁移过程中产生新数据：

```bash
# 旧服务器
systemctl stop hanmo-server
systemctl status hanmo-server --no-pager
```

4. 停止后不要再用管理端/小程序写入。小程序会提示网络错误，属于预期。

> 如果无法停机，至少对数据库加读锁，但本项目更推荐短时间停机，简单可靠。

### 5.2 备份数据库

旧服务器：

```bash
STAMP=$(date +%Y%m%d-%H%M%S)
mkdir -p /data/hanmo/backups/migration
mysqldump \
  -h127.0.0.1 -uhanmo -p \
  --single-transaction --routines --triggers \
  --default-character-set=utf8mb4 --no-tablespaces \
  hanmo_calligraphy | gzip -9 > /data/hanmo/backups/migration/hanmo-db-$STAMP.sql.gz
ls -lh /data/hanmo/backups/migration/
```

检查文件不是 0 字节：

```bash
gzip -t /data/hanmo/backups/migration/hanmo-db-$STAMP.sql.gz
```

### 5.3 备份上传文件

```bash
tar -C /data/hanmo -czf /data/hanmo/backups/migration/hanmo-uploads-$STAMP.tar.gz uploads
ls -lh /data/hanmo/backups/migration/hanmo-uploads-$STAMP.tar.gz
```

> 上传目录必须与数据库同批次备份，否则会出现作品/环境图片 404。

### 5.4 备份配置与程序

```bash
cp /etc/hanmo/hanmo.env /data/hanmo/backups/migration/hanmo.env.$STAMP
chmod 600 /data/hanmo/backups/migration/hanmo.env.$STAMP
cp /data/hanmo/app/hanmo-server.jar /data/hanmo/backups/migration/hanmo-server-$STAMP.jar
sha256sum /data/hanmo/backups/migration/hanmo-server-$STAMP.jar
```

### 5.5 传输到新服务器

在新服务器上创建目录；在旧服务器执行：

```bash
NEW_IP=新服务器IP
scp /data/hanmo/backups/migration/hanmo-db-$STAMP.sql.gz root@$NEW_IP:/tmp/
scp /data/hanmo/backups/migration/hanmo-uploads-$STAMP.tar.gz root@$NEW_IP:/tmp/
scp /data/hanmo/backups/migration/hanmo.env.$STAMP root@$NEW_IP:/tmp/hanmo.env
scp /data/hanmo/backups/migration/hanmo-server-$STAMP.jar root@$NEW_IP:/tmp/hanmo-server.jar
```

如果用 `rsync` 更快：

```bash
rsync -avz --progress /data/hanmo/backups/migration/ root@$NEW_IP:/tmp/migration/
```

### 5.6 新服务器恢复数据库

新服务器：

```bash
# 创建空库（如果还没建）
mysql -uroot -p -e "CREATE DATABASE IF NOT EXISTS hanmo_calligraphy DEFAULT CHARACTER SET utf8mb4 COLLATE utf8mb4_general_ci;"

# 恢复
gunzip -c /tmp/hanmo-db-$STAMP.sql.gz | mysql -uroot -p hanmo_calligraphy
```

如果用 `sudo mysql`（Ubuntu auth_socket）：

```bash
gunzip -c /tmp/hanmo-db-$STAMP.sql.gz | sudo mysql hanmo_calligraphy
```

验证：

```bash
mysql -h127.0.0.1 -uhanmo -p -e "USE hanmo_calligraphy; SHOW TABLES; SELECT COUNT(*) FROM student;"
```

### 5.7 新服务器恢复上传文件

```bash
mkdir -p /data/hanmo/uploads
tar -C /data/hanmo -xzf /tmp/hanmo-uploads-$STAMP.tar.gz
chown -R hanmo:hanmo /data/hanmo/uploads
chmod 755 /data/hanmo /data/hanmo/uploads
# Nginx 用户加入 hanmo 组，否则 Nginx 读取 640 的上传文件会 403
usermod -aG hanmo www-data    # Alibaba Cloud Linux 用 nginx
systemctl restart nginx
```

验证：

```bash
du -sh /data/hanmo/uploads
find /data/hanmo/uploads -type f | wc -l
```

### 5.8 恢复环境变量

```bash
cp /tmp/hanmo.env /etc/hanmo/hanmo.env
chown root:hanmo /etc/hanmo/hanmo.env
chmod 640 /etc/hanmo/hanmo.env
```

检查：

```bash
grep -E 'DB_|JWT_SECRET|UPLOAD_DIR|CORS_ORIGINS|WX_' /etc/hanmo/hanmo.env
```

注意：

- `DB_PASSWORD` 改新服务器 MySQL 的密码（如果新库密码不同）。
- `UPLOAD_DIR=/data/hanmo/uploads`。
- `CORS_ORIGINS` 如果是新域名，改成新域名。
- `JWT_SECRET` 与旧服务器保持**完全一致**，否则所有已登录用户需要重新登录（也可以接受，但要提前说明）。

### 5.9 部署后端

```bash
install -o hanmo -g hanmo -m 640 /tmp/hanmo-server.jar /data/hanmo/app/hanmo-server.jar
cp /tmp/hanmo-server.service /etc/systemd/system/hanmo-server.service
systemctl daemon-reload
systemctl enable hanmo-server
systemctl start hanmo-server
curl http://127.0.0.1:8080/actuator/health
```

> 如果新服务器还没有 systemd 文件，按部署手册第 5.4 节先安装。

### 5.10 部署管理端与 Nginx

按部署手册第 6 节：

1. `/var/www/hanmo-admin` 放最新 `dist`。
2. 配置 Nginx。
3. **域名不变**：把旧服务器 `/etc/letsencrypt` 整个目录复制到新服务器，保持路径一致：

```bash
# 旧服务器
tar -C / -czf /tmp/letsencrypt.tar.gz etc/letsencrypt
scp /tmp/letsencrypt.tar.gz root@新服务器:/tmp/

# 新服务器
tar -C / -xzf /tmp/letsencrypt.tar.gz
systemctl reload nginx
# DNS 尚未切换时不要执行 renew --dry-run，验证会指向旧服务器
```

DNS 切换完成后，再在新服务器验证续期：

```bash
certbot renew --dry-run
```

或在 DNS 切换后重新申请：

```bash
certbot certonly --webroot -w /var/www/certbot -d hanmo.example.com
```

4. 如果是新域名，按部署手册重新申请新证书。

### 5.11 DNS 切换

确认新服务器本地一切正常后，再切 DNS：

```text
旧 A 记录：hanmo.example.com → 旧 IP
新 A 记录：hanmo.example.com → 新 IP（TTL 300）
```

在域名控制台修改；等待生效：

```bash
nslookup hanmo.example.com 8.8.8.8
dig +short hanmo.example.com
```

切换后观察：

```bash
curl -I https://hanmo.example.com/
curl https://hanmo.example.com/api/public/home
```

> 如果使用新域名，先在新域名解析并验证 HTTPS，再更新小程序域名。

## 六、迁移后验证

### 6.1 数据一致性

在新服务器执行：

```bash
mysql -h127.0.0.1 -uhanmo -p -e "
USE hanmo_calligraphy;
SELECT 'student' AS t, COUNT(*) AS c FROM student
UNION ALL SELECT 'parent_student', COUNT(*) FROM parent_student
UNION ALL SELECT 'enrollment', COUNT(*) FROM enrollment
UNION ALL SELECT 'payment_record', COUNT(*) FROM payment_record
UNION ALL SELECT 'attendance', COUNT(*) FROM attendance
UNION ALL SELECT 'leave_request', COUNT(*) FROM leave_request
UNION ALL SELECT 'work', COUNT(*) FROM work
UNION ALL SELECT 'hour_ledger', COUNT(*) FROM hour_ledger;
SELECT SUM(amount) AS payment_total FROM payment_record;
SELECT SUM(remaining_hours) AS remaining_total, SUM(used_hours) AS used_total FROM hour_account;"
```

与迁移前记录逐项对比，必须一致。

### 6.2 图片检查

随机打开几个作品/机构图片 URL：

```bash
curl -I https://hanmo.example.com/uploads/2026/10/xxxx.jpg
```

应返回 200。若 404：

- 检查 Nginx `alias /data/hanmo/uploads/;`
- 检查文件是否存在、权限是否 755
- 检查 `UPLOAD_DIR` 是否一致

### 6.3 功能检查

- [ ] 管理端登录
- [ ] 数据看板有数据
- [ ] 学员列表、档案、课时流水
- [ ] 报名记录、缴费记录
- [ ] 课表、点名
- [ ] 请假审批
- [ ] 作品墙、作品详情
- [ ] 机构资料、环境图片、师资、资质、公告
- [ ] 家长小程序登录、课表、请假、报名、课时
- [ ] 教师小程序登录、点名、审批、上传
- [ ] 图片上传
- [ ] 统计报表
- [ ] HTTPS 证书有效
- [ ] 微信开发者工具 request 域名无报错

### 6.4 微信检查

如果域名不变：无需改微信配置；如果换了域名：

1. 微信公众平台 → 开发管理 → 服务器域名，更新 request/uploadFile/downloadFile。
2. 修改 `miniprogram/config.js` 的 `production.baseUrl/apiBase`。
3. 重新上传小程序版本 → 提交审核 → 发布。
4. 旧版本用户可能仍请求旧域名，旧域名需保持可用一段时间或做 301。

## 七、回滚方案

### 7.1 数据异常或功能不可用

1. 把 DNS A 记录改回旧服务器 IP。
2. 启动旧后端：

```bash
systemctl start hanmo-server
```

3. 确认旧站可用：

```bash
curl https://hanmo.example.com/api/public/home
```

4. 新服务器保留现场，排查问题，不要立即删除。

### 7.2 只回滚程序版本

```bash
# 新服务器
ls /data/hanmo/backups/releases/
install -o hanmo -g hanmo -m 640 /data/hanmo/backups/releases/hanmo-server-旧时间.jar /data/hanmo/app/hanmo-server.jar
systemctl restart hanmo-server
```

### 7.3 只回滚数据库

```bash
gunzip -c /data/hanmo/backups/migration/hanmo-db-旧时间.sql.gz | mysql -uroot -p hanmo_calligraphy
```

> 回滚数据库会丢失迁移后新产生的数据，必须先确认。

## 八、旧服务器下线

观察新服务器至少 **7 天**，确认：

- 无 500/502
- 无数据丢失
- 家长/教师使用正常
- 备份任务正常
- 证书自动续期正常

再执行：

1. 旧服务器再备份一次，下载到本地保存：

```bash
sudo -u hanmo /data/hanmo/scripts/backup.sh
scp /data/hanmo/backups/最新备份 root@你的电脑:/备份目录/
```

2. 保留旧服务器 30 天（关机但不释放），确认无回滚需求后再释放。
3. 释放旧服务器前，确认 DNS 已完全指向新服务器、微信域名已更新。

```bash
# 旧服务器冻结
systemctl stop hanmo-server

# 数据库备份

# 新服务器恢复
gunzip -c /tmp/hanmo-db-xxx.sql.gz | sudo mysql hanmo_calligraphy

chown -R hanmo:hanmo /data/hanmo/uploads

# 启动
```
