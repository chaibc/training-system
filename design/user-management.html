01 / MODEL

先说结论：四类对象，三种账号，四种角色

后台账号、教师账号、家长账号相互独立；一个账号只能拥有一种身份。学员只建档，不是登录账号。
WEB ADMIN

后台账号

用户名 + 密码登录
角色：管理者 / 教务
数据范围：全部业务数据
创建：管理者创建；管理者账号唯一
MINI PROGRAM

教师账号

微信授权 + 手机号匹配
角色：教师
数据范围：所带班级与学员
开通：后台创建，微信登录自动匹配
MINI PROGRAM

家长账号

微信授权自动创建
角色：家长
数据范围：已绑定子女
绑定：提交申请，教务审核
PROFILE ONLY

学员档案

不是登录账号
归属：由家长账号绑定
数据：档案 / 课时 / 课表 / 请假 / 作品
权限：随绑定家长可见
关键口径：一个账号只能拥有一种身份，教师账号与家长账号互斥，不提供身份切换。教师账号由后台创建，教师微信登录后按手机号匹配；小程序不提供「申请教师身份」。学员不单独登录，避免未成年人账号与重复建档。
02 / ROLES

内置角色与权限边界

首期不做自定义角色，避免权限碎片化；角色固定，权限可按模块微调，后续确有需要再开放自定义。
角色适用账号可访问模块数据范围关键限制
管理者后台账号全部模块，含用户与权限全机构账号唯一；仅管理者可修改用户与权限；不可新增/停用/删除
教务后台账号学员、报名、班级排课、点名消课、请假、作品；课程/价格只读全机构不可见机构内容、基础数据、业务规则、用户与权限
教师小程序教师身份教师工作台、点名消课、请假审批、上传作品所带班级与学员不能查看其他班级；不能修改价格与账号
家长小程序家长身份首页、课程、报名、课表、请假、作品、档案已绑定子女只能查看/操作本人子女；关键信息修改需教务审核
03 / MATRIX

权限矩阵：后台模块级

「查看」是最低权限；新增、编辑、删除、审批等动作单独控制。小程序端按身份与数据范围控制，不套用后台矩阵。
模块管理者教务说明
数据看板 / 统计报表全部查看报表导出属于查看权限内的动作
学员管理全部全部课时调整需填写原因并留痕
报名与缴费全部全部线下缴费登记；无线上支付
课程与定价全部仅查看教务可查看课程与价格，不修改
班级与排课全部全部调课、停课、代课均留痕
点名与消课全部全部消课修正需原因
请假审批全部全部补课安排由教务执行
作品管理全部全部授权与审核是发布前置条件
机构内容全部不可见机构资料、师资、资质、公告
基础数据全部不可见分类、阶段、班型、教室等
业务规则全部不可见规则变更影响全机构
用户与权限全部不可见仅管理者可修改；管理者账号唯一
04 / LIFECYCLE

账号生命周期

账号从创建到停用、解绑与归档，所有关键动作留痕；停用不删除历史数据。
1
创建 / 首次登录后台账号由管理者创建（管理者唯一）；教师由后台师资档案创建；家长首次微信登录自动创建。
2
账号匹配 / 绑定教师微信登录按手机号匹配后台账号；家长提交子女绑定，教务审核后生效。
3
授权使用按角色进入后台或小程序，数据范围随角色与绑定关系计算。
4
变更 / 停用角色、手机号、状态可变更；仅管理者可修改用户与权限；停用立即失效，历史记录保留。
5
解绑 / 归档解绑需审核；学员结课或离校后账号只读，不删除业务数据。
安全口径：后台密码使用 BCrypt 存储；连续输错 5 次锁定 5 分钟；不做二次验证；JWT 有效期 8 小时；停用或改密后旧 Token 失效。
05 / BINDING

家长绑定与教师账号开通

家长绑定子女需教务审核；教师账号由后台创建，微信登录后按手机号自动匹配，小程序不提供教师身份申请入口。

家长绑定子女

  • ① 家长提交：绑定已有学员（姓名 + 学员编号 + 监护人手机号后四位）或新建学员。
  • ② 教务审核：核对学员档案与监护人信息；通过后家长才能看到课表、课时与请假记录。
  • ③ 多子女：一个家长账号可绑定多个子女，切换查看。
  • ④ 多监护人：一个学员最多 2 个有效监护人，其中 1 个主联系人；第二个需教务审核。
  • ⑤ 解绑：家长发起申请，教务审核后生效；教务也可强制解绑并留痕。

教师账号开通

  • ① 后台建档：管理者在「机构内容 → 师资团队」新增教师，登记姓名与手机号，系统同步创建教师账号。
  • ② 微信登录：教师用微信打开小程序并授权手机号；无需短信验证，也无需提交教师身份申请。
  • ③ 自动匹配：手机号与后台教师账号一致 → 直接进入教师工作台；不一致 → 提示联系教务，不提供自助申请。
  • ④ 身份互斥：教师账号与家长账号互斥；同一微信不能同时拥有两种身份，也不提供身份切换。
  • ⑤ 变更 / 解绑：管理者修改手机号或解绑后，教师重新登录匹配；历史点名与审批记录保留。
06 / SECURITY

数据范围与安全规则

小机构不需要复杂权限引擎，但必须有清晰的数据边界与可追溯的账号变更。

数据范围

  • 全机构：管理者、教务；教务不可见配置类模块与用户管理。
  • 所带班级：教师只能查看自己所带班级、学员、点课与请假。
  • 本人子女：家长只能访问已绑定且状态有效的学员数据。
  • 只读历史：学员结课/停课后，家长仍可查看历史课时与作品，但不能发起新业务。

安全与审计

  • 最小必要：手机号、身份证等敏感信息脱敏展示；家长只看本子女。
  • 登录保护：密码 BCrypt；连续输错 5 次锁定 5 分钟；首登强制改密；暂不启用二次验证。
  • 账号变更：创建、角色变更、停用、重置密码、绑定/解绑均记录操作人、时间、IP。
  • 不可删除：账号只停用不物理删除；管理者账号唯一且不可停用；保证课次、缴费、作品历史可追溯。
