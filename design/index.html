05 / USER

用户管理逻辑（本轮补充）

四类对象、三种账号、四种角色：后台账号、教师账号、家长账号相互独立；一个账号只能拥有一种身份；学员只建档不登录。
!
已确认口径：后台账号唯一管理者 + 教务；不做二次验证，连续输错 5 次锁定 5 分钟；仅管理者可修改用户与权限；家长账号与教师账号互斥，同一账号只能一种身份；教师账号由后台创建，微信登录按手机号自动匹配，无需短信验证，小程序不提供教师身份申请；老师兼家长使用另一个微信账号；家长绑定需教务审核，一个学员最多 2 个有效监护人；学员结课后家长可查看历史但不能发起新业务；游客可浏览机构 / 课程 / 师资 / 作品 / 试听，报名与个人数据需登录。

角色与数据范围

  • 1
    管理者 / 教务后台账号，用户名密码登录；管理者账号唯一且仅管理者可修改用户与权限；教务不可见配置、规则与用户。
  • 2
    教师教师账号由后台创建；微信登录按手机号匹配，只看所带班级与学员，不提供身份申请或切换。
  • 3
    家长微信授权自动创建，绑定子女后只看本人子女；与教师账号互斥；关键信息修改需教务审核。
  • 4
    学员只是档案，不是账号；所有权限随绑定家长计算。

原型入口

  • A
    用户管理逻辑评审稿 →账号模型、权限矩阵、生命周期、绑定链路与待确认项。
  • B
    后台「用户与权限」→用户账号、角色权限、家长绑定审核、登录与变更记录。
  • C
    小程序「账号与绑定」→家长微信账号、子女绑定、添加学员、解绑申请。
  • D
    小程序「登录 / 授权」→未登录状态、微信一键登录、游客浏览与公开内容范围。
用户管理为开发前置的业务逻辑补充，不计入原需求 77 项功能清单；正式开发时以确认后的角色、字段与数据范围为准。
06 / DEMO

建议演示路径

按真实业务顺序操作，能看到内容在后台维护、在小程序只读展示的口径设计。

家长端：从了解课程到请假

  • 1
    首页 → 课程体系 → 课程详情切换硬笔 / 软笔 / 幼小衔接分类，查看班型价格与内容大纲。
  • 2
    预约试听 / 报名登记填写表单并提交，进入成功页；报名记录中查看「待确认 → 待缴费 → 已入班」状态与线下缴费说明。
  • 3
    我的课表 → 课次详情 → 请假申请切换子女、按天筛选；提交请假后进入结果页，在请假记录中查看审批状态与补课入口。
  • 4
    作品墙 → 作品详情筛选作品、点赞、分享好友或朋友圈、提交留言（审核后展示），查看机构公告。
  • 5
    我的 → 学员档案 / 课时账户 / 成长相册查看档案、课时流水、上课记录与作品时间线。

管理端：内容维护与教务处理

  • 1
    课程与定价 → 课程管理新建/编辑课程，设置分类、阶段、适龄段与首页推荐，体验上下架与删除。
  • 2
    课程与定价 → 班型与价格新增、编辑、停售、删除课程班型价格；切换课程查看对应价格。
  • 3
    课程与定价 → 内容大纲选择课程，新增/编辑阶段，切换显示/隐藏并调整顺序，小程序端只展示可见阶段。
  • 4
    基础数据维护课程分类、阶段、班型、教室、请假原因、缴费方式与试听时段。
  • 5
    机构内容编辑机构资料、师资、资质与公告；作品管理完成授权与审核；报名与缴费登记线下收款。

原型约定

· 所有数据为演示样例，不代表真实机构经营数据；
· 手机号、身份证等敏感信息均按脱敏展示；
· 报名、续费、补费等金额仅用于流程演示；
· 未接入后端、微信登录、支付接口与地图接口，相关按钮以弹层 / 提示说明真实调用；
· 后台的内容修改为原型内演示，不在刷新后持久化；交付开发时以同一套字段与状态口径落地；
· 本轮不含校区、活动、导入、消息通知与线上缴费。
